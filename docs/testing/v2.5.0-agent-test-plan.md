**For:** Mistral Vibe, OpenAI Codex, Claude Code, and one person for the
browser, PDF and draw.io checks.

**What:** draft PR #8 (`claude/architecture-diagrams-feature-plan-nz5q57`),
built against the locked plan
[`docs/development-plan-2026-10-v2.5.0.md`](../development-plan-2026-10-v2.5.0.md)
(revision 4). §4a holds its contracts and §8 its acceptance.

**Goal:** prove that the skills *work* (commands, rules, exit codes,
links) and that their *output is good*. Good output means correct EDGY,
correct C4, readable pictures, every link resolving, and honesty about
what is missing.

**Status:** revision 5 — **LOCKED** by the owner (2026-10-17), together with the development plan. Phase 3 builds against it.
Revision 1 was reviewed by Codex (TP1–TP9) and Vibe (V1–V9), revision 3
by Codex again (R1–R3); see §11. Commands use the
interfaces the plan specifies. If phase 3 changes a name, the test plan
is updated in the same commit, and plan §11 records the change.

## 0. Rules for every tester

- Use only **fictional** data: Acme Transit, Nordlake Ferries, or a
  company you invent. Never a real client and never a real person.
- Work on a fresh clone of the PR branch, and do not push to it. Report
  in one PR comment per agent, using the template in §9.
- Python 3.8+, and `pip install pyyaml`. Chromium or Chrome is needed for
  P02 only.
- Set:
  ```bash
  R=$PWD
  D=$R/skills/documentation/edgy-diagram
  A=$R/skills/architecture/edgy-assessment
  C=$R/skills/documentation/edgy-c4
  OUT=$(mktemp -d)
  ```
- A test **passes** only when every *Expected* line holds. "Mostly" is a
  fail with a note.
- When you compare bytes, use `EDGY_TEXT_TABLE_ONLY=1`, as the gates do.
- **Pixel review is part of the test.** In v2.4.0, lint reported 0 / 0 on
  pictures that people could not read. Look at the PNG of every page type
  you produce, and say in the report whether you did (§9).

- **Static and browser results are reported separately.**
  - A missing browser is a visible SKIP and exits 2.
  - A browser that is installed but fails to launch exits 1.
  - Neither one is a browser PASS.
  - Dynamic assertions (P02, and the browser parts of K10, K11, P04 and
    SEC04) are taken from a run on a working Chrome at the **exact
    candidate SHA**, and the report lists the self-test steps it ran.
    "CI green" alone does not prove that a new scenario ran.
- **Pixel review without a browser:** rasterise the native SVG
  (`edgy_render.py`, Inkscape, or MuPDF). This shows layout, but it
  proves nothing about DOM interaction, animation or browser security.
- **Fallbacks never waive a person's item.** P03, H01 and H02 need named
  browser, draw.io and PDF evidence before the release.

## 2. Track A: gates, install and adapters

**Isolated install roots** (used by G02, G04, K02 and K10). The installed
scripts must never see the checkout. Handler discovery searches
`EDGY_NOTATION_PATH`, then the installed sibling skills, then the
repository checkout (`edgy_notation._search_dirs()`). Do this:

```bash
unset EDGY_NOTATION_PATH
WORK=$(mktemp -d); cp -r $D/examples $C/examples $A/examples $WORK/   # copy the inputs first
ROOT_D=$(mktemp -d); HOME=$ROOT_D bash adapters/claude-code/install.sh edgy-diagram --source=local
ROOT_DC=$(mktemp -d); HOME=$ROOT_DC bash adapters/claude-code/install.sh edgy-c4 --source=local   # pulls edgy-diagram
ROOT_ALL=$(mktemp -d); HOME=$ROOT_ALL bash adapters/claude-code/install.sh --all --source=local    # all six skills
cd $WORK                                                                  # never run from inside the checkout
handlers() { (cd "$1/.claude/skills/edgy-diagram/scripts" && env -u EDGY_NOTATION_PATH python3 -c 'import edgy_notation; print(sorted(edgy_notation.handlers()))'); }
handlers $ROOT_D    # expected: []
handlers $ROOT_DC   # expected: ['c4']
handlers $ROOT_ALL  # expected: ['c4']
ls $ROOT_D/.claude/skills    # expected exactly: edgy-diagram
ls $ROOT_DC/.claude/skills   # expected exactly: edgy-c4 edgy-diagram
ls $ROOT_ALL/.claude/skills  # expected exactly: edgy-assessment edgy-c4 edgy-deep-dive edgy-diagram edgy-framework edgy-target-state
```

Each root has one job:
- `$ROOT_D` is the no-handler case;
- `$ROOT_DC` is the isolated C4 and dependency case;
- `$ROOT_ALL` is a user's full install (G02).

**SEC03 C4 declarations: rejected versus accepted inputs.** The policy
is recorded in plan §11:
- **Rejected:** malformed syntax; ids that break the graph-id pattern;
  **C4 container** ids longer than 64 characters. EDGY ids keep the
  v2.4.0 rule: the pattern applies and there is no length limit.
- **Accepted:** well-formed text, however hostile. It is shown
  literally, and an accepted id is an inert index key.

*a) Rejected:*
- an unterminated `{`;
- a container id `a b`, `../x`, `x"y` or `__proto__` (pattern: it must

- a container id of 65 characters (the C4 length limit);
- `level: ../x` (not `context` or `container`);
- `system:` with no value.

*Expected:* a controlled E-level error naming the page and the input,
with exit 2 and no output file. Never a traceback.

*b) Accepted, inert:*
- a container **named** `</template><script>alert(1)</script>`;
- a technology `"><img src=x onerror=alert(1)>`;
- container ids `constructor` and `toString` (they match the pattern);
- a 64-character container id (the boundary);
- an **EDGY** element id of 65 and of 200 characters (`CAP-` plus
  digits). It is valid, as in v2.4.0.

*Expected:*
- exit 0, and the page is written;
- the names show literally in draw.io, in the SVG preview and in the
  presenter (P04), with no script run;
- the ids work as ordinary keys: the C4 index and the presenter look
  them up correctly, and no other container or object property changes.
  The index uses plain dict and `Map` lookups, never object property
  assignment;
- no traceback and no uncaught browser error.

*c) Compatibility and units:*
- The `compat-1.9` fixtures (M03) include a model with a
  200-character element id. It validates and gives byte-identical
  output, as in v2.4.0.
- The index unit tests insert `__proto__`, `constructor` and `toString`
  directly as keys at the index boundary, below the parser. Each lookup
  returns only its own entry, and no prototype changes.

**SEC04 Routes.** In the browser self-test (`route-malformed`) and by
