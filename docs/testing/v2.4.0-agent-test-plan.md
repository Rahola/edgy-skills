# v2.4.0 test plan for agents — architecture views and presenter-lite

**For:** Mistral Vibe, OpenAI Codex, Claude Code (and one person for the
browser checks). **What:** the draft PR of v2.4.0
(`claude/architecture-diagrams-feature-plan-nz5q57`). **Goal:** prove that
the skills *work* (commands, rules, exit codes) and that their *output is
good* (correct EDGY, readable, complete, honest about what is missing).
v2.5.0 (`edgy-c4`, more presenter effects) is **out of scope**.

Background: `docs/development-plan-2026-10-architecture-views.md` (rev 5,
§9 acceptance, §12 deviations), `CHANGELOG.md` → v2.4.0,
`skills/documentation/edgy-diagram/references/architecture-views.md`.

## 0. Rules for every tester

- Use only **fictional** data (Acme Transit, or a company you invent). Never
  a real client, never a real person. Nothing you write to the PR may name
  one.
- Work on a fresh clone of the PR branch. Do not push to it. Report findings
  as one PR comment per agent (template in §8).
- Run from the repository root unless a step says otherwise. Python 3.8+,
  `pip install pyyaml`. Chromium/Chrome only for P02.
- Set `R=$PWD`, `D=$R/skills/documentation/edgy-diagram`,
  `A=$R/skills/architecture/edgy-assessment`, `OUT=$(mktemp -d)`.
- A test **passes** only when every *Expected* line holds. "Mostly" is a
  fail with a note.
- With Pillow installed, text is measured with real fonts and output can
  differ from the shipped examples by a pixel. That is expected. The gates
  force the glyph tables (`EDGY_TEXT_TABLE_ONLY=1`); use the same when you
  compare bytes.

## 3. Track B — generator functions (edgy-diagram)

**D01 Shipped examples, strict.**
```bash
cd $D; for f in application-map application-by-capability-map process-chain-map process-swimlane-map capability-view-map; do
```

*Expected:* `0 error(s), 0 warning(s)` for each. Look at every PNG (§7
rubric).

**D02 Application map: placement rules.** Copy
`examples/application-by-capability-map.txt` and:
1. remove `{primary: true}` from an application that two capabilities

   how many such applications there are.
2. delete every `requires` to one application. *Expected:* it lands in
   **Not required by a capability**.
3. add `[external]` to an application. *Expected:* an **External systems**
   column.
4. add 13 `transfers`. *Expected:* by default no integration edges, the
   cards count them (`edges: direct` brings them back).

**D03 Owners and integrations.** On an application map, remove the owner
(`manages` / `{owner:}`) of one application, and the `{data:}` of one
`transfers`. *Expected:* `W124` as a **note**, and as a **warning** after
adding `ownership: required` to the page; `W125` for the integration.

**D04 Value chain.** In `examples/process-chain-map.txt`, delete
`{band: …}` from one L1 process and give one L2 a different band than its
parent. *Expected:* two `W126` warnings; L2 stacked under its L1; with

**D05 Swimlane.** `examples/process-swimlane-map.txt`. *Expected:* one lane
per performing actor, steps as a staircase in input order, the assets a step

**D06 Capability view and evidence statuses.**
`examples/capability-view-map.txt` (pages `Capability · CAP-05 …` and
`… CAP-06 …`). *Expected:* actors above, processes left, resources right,
data with CRUD below, products bottom. Remove `gaps: …` from CAP-05:
*Expected:* `W127 … not investigated` as a **warning**, and in
`--qa` output `model_gaps[]` has `{element_id: CAP-05, band: products,
status: not_investigated}`. Set the status to `confirmed_absent`:

**D07 Matrices.** Pages `Capability × application` and `CRUD`. *Expected:*
● for requires, ◉ for the primary, CRUD letters exactly as in

**D08 Identity errors.**
```bash
cat > $OUT/dup.txt <<'EOF'
```

**D09 Notation fails closed.** An input with `notation: c4` (no handler

**D10 Derived views do not invent.** Generate the eval model:

**D11 Determinism.** Generate the same input twice, and once more with

**D12 Languages.** Set `language: fi` (then `fr`, `de`) on

## 5. Track D — presenter-lite

Build first:
`python3 $D/scripts/edgy_generator.py $OUT/acme-views.txt --output $OUT/acme.drawio --present $OUT/acme.html`

**P01 Self-contained and locked down.** *Expected:* no `http://` or
`https://` in any `src` / `href`; a CSP `<meta>` with `script-src` and
`style-src` as sha256 hashes and `connect-src 'none'`; the file opens
offline. `python3 $D/scripts/test_present.py` passes; without Chrome its
browser part is a visible SKIP.

**P02 Browser self-test.** With Chromium/Chrome:
`python3 $D/scripts/test_present.py`. *Expected:* the self-test (zoom,
highlight, search, change filter, `T` a no-op on a page without changes)
reports 0 failures and 0 `window.onerror`.

**P03 Person, three browsers (Chrome, Firefox, Safari).** Open
`acme.html` and `examples`-based presentations. *Expected, all five effects
and nothing more:*
1. card wall → click zooms smoothly into the view, crisp at every frame,
   Esc / back returns;
2. hover or keyboard focus highlights an element and its neighbours, dims
   the rest, and the other views' cards show how many times it appears;
3. ⌘K / Ctrl+K finds elements by name and id and jumps there;
4. `T` cycles all → current (new hidden) → target (removed hidden) on a
   page with `{change:}`, and shows a "no change annotations" toast
   elsewhere;
5. ← / → page, `F` full screen, the deep link `#/view/<page>/<id>?state=target`
   opens that state, print gives one view per page.
Also: with *reduce motion* set in the OS, every animation is a cut; all
elements reachable by Tab with a readable `aria-label`; the diagram stays on a
light card in dark mode.

**P04 Hostile input stays inert.**
```bash
cat > $OUT/hostile.txt <<'EOF'
elements:
  - capability: "<script>alert(1)</script>" {id: CAP-01}
  - asset: "Fare engine <img src=x onerror=alert(1)>" {id: APP-01, kind: application, hosting: "x\" onload=\"alert(1)"}
relationships:
  - "CAP-01" -> "APP-01": "requires"
EOF
python3 $D/scripts/edgy_generator.py $OUT/hostile.txt --output $OUT/h.drawio --present $OUT/h.html
```
*Expected:* no alert in any browser; `grep -c '<script>alert\|<img src=x' $OUT/h.html` is 0; the texts show
literally; only the three `<script>` tags of the template exist (one code, two
`application/json`). Try your own variants (style values with `;` and `"`,
page names with `</template>`, ids with quotes).

**P05 Size.** 30 views stay under 1.5 MB (`--max-mb` default); a bigger
document exits 3 with a clear message.

## 6. Track E — the skills used by an agent (prompt tests)

Install the skills for your agent (G02), start a **new** session in an empty
folder, and give the prompt as written. Do not help beyond the prompt. Keep the
transcript summary and the produced files for §7. Each test lists what a
good run **must** do and what it **must not** do.

**S01 Application landscape from prose (edgy-diagram).**
> "Draw the application landscape of Nordlake Ferries (fictional): booking web and app, a CRM, a fare engine, a payment gateway (SaaS), a vessel tracking platform, a data warehouse; booking sends reservations to the CRM over REST, the fare engine sends fare rules to booking, vessel tracking streams positions to the warehouse over Kafka. The fare team owns booking and the fare engine; IT owns the rest. Mark the CRM for migration and the data warehouse for investment. Deliver a draw.io file and a PNG."

*Must:* write a TXT and use `edgy_generator.py` (not hand-written XML);
applications as `asset … {kind: application|platform|integration}`, data as
`{kind: data}` named on the `transfers`; `{time: migrate|invest}`; owners
via `manages` or `{owner:}`; run `edgy_lint.py`, look at the preview, report
the result and any `Note:`. *Must not:* invent element types ("Application",
"System"), use `uses` from an actor to an asset (E010), colour cards by
lifecycle (fill is the facet colour; TIME is a badge).

**S02 Processes (edgy-diagram).**
> "Same company: management processes 'Steer the company'; core 'Plan sailings' (timetable, capacity), 'Sell trips' (pricing, booking), 'Operate vessels'; support 'Maintain fleet'. Show the process landscape, and a swimlane of 'Sell trips' with the pricing team and the customer service desk; pricing needs the fare engine."

*Must:* `process_view: chain` with `{band:}` and `contains`; a swimlane with
lanes from `performs` and chips from `requires`; 0 lint errors. *Must not:*
put the customer service desk as a process, draw `contains` edges on the
chain.

**S03 Capability view with honest gaps (edgy-diagram + edgy-framework).**
> "Show everything about the capability 'Trip sales' of Nordlake Ferries: who has it, which processes realise it, which applications and data it needs (with CRUD), which products need it. We do not know the products yet."

*Must:* `map_type: capability-view` with `focus:` (or a model page and
`expand:`); an empty products band reported as **W127 not investigated /
unknown** and presented as an *open question*, not as a finding about the
company; CRUD on the data edges. *Must not:* invent products to fill the
band.

**S04 Modelling questions (edgy-framework 1.7.0).**
> "Is 'CRM' a capability or an asset? And our capability is called 'Booking' while the booking system is also called 'Booking' — is that a problem? Where do I put customer data that both CRM and booking keep?"

*Must:* CRM = Asset `{kind: application}`; capabilities stay
system-independent; the same name is a review question (S013), not a rule
to rename; one master per data set (`{master: true}`), two claimants = a
decision to make. Cites the *Modelling applications, data and actors*
section's logic, in the user's language.

**S05 Assessment with architecture views (edgy-assessment 1.10.0).**
> "Run an EDGY assessment of Nordlake Ferries (fictional; use the facts in this prompt only): [paste S01 + S02 facts]. Include the application landscape and capability views."

*Must:* write `edgy-model.json` as **format 1.9** (asset kinds,
`relationships[]` between ids, `schema_version: "1.9"`), validate it, use
`edgy_model_to_txt.py --views …` for the views (not hand-written TXT), report
`model_gaps` as open questions and only `confirmed_absent` as findings; the
usual Phase 4b semantic review and Phase 5 checks. *Must not:* present an
unknown as a fact, use any real company data.

**S06 Target state with ownership (edgy-target-state 1.2.0).**
> "We are planning the target architecture for Nordlake Ferries' sales. Show the current application landscape and which applications have no owner."

*Must:* `ownership: required` on the application page → missing owners as
**W124 warnings**; TIME as current lifecycle, the transition overlay for the
target; `edgy_model_diff.py` if two models exist.

**S07 Deep dive on a 1.9 model (edgy-deep-dive 1.1.1).** Give the agent
`$A/examples/architecture-model.json` and ask for a capability ×
organisation deep dive. *Must:* read `organisation` as an array without
failing; only use elements in the model.

**S08 Out of scope (v2.5.0).**
> "Draw a C4 container diagram of the fare engine."

*Must:* say plainly that C4 is not part of these skills yet (planned as
`edgy-c4`, v2.5.0) and offer what exists (application map, capability
view). *Must not:* fake a C4 diagram in EDGY shapes or claim C4 support.
Record what the agent does — this is an observation, not a gate.

## 7. Track F — output quality review (rubric)

Rate every produced map (D01, D10, M03, S01–S06) on six criteria, **0 / 1 / 2**:

| Criterion | 2 = good | 1 = acceptable | 0 = fail |
|-----------|----------|----------------|----------|
| **EDGY correctness** | only EDGY elements; core links with correct verbs; applications and data as Asset kinds; influence verbs dashed | one questionable verb or type | invented types, wrong core link, E-errors |
| **Readability** | no edge through a card, no label on a card or off the page, no overlap, text ≥ 6 pt at report size | one minor crowding | W111–W114 or an unreadable area |
| **Completeness** | every element and relationship the view type should show is there, nothing extra | one omission explained by a `Note:` | silent omissions or invented content |
| **Traceability** | explicit ids on every card; the same id = the same element on every view | a few slug ids on a one-off page | ids missing or conflicting |
| **Honesty** | gaps, foldings and suppressed links reported (`Note:`, `model_gaps[]`); unknowns as questions | one report missing | an unknown shown as a fact |
| **Language** | one language per page, verbs / legend / badges localised | one leftover word | mixed languages |

A view **passes** with ≥ 10/12 and no 0. Attach the PNG of every view that
scores below 10.

**Q01** Rate the 22 eval pages (D10) — Claude and Vibe independently; report
disagreements of 2 points or more on a criterion.
**Q02** Rate the agent-produced maps of S01–S06 per agent; compare Vibe vs
Claude runs of the same prompt.
**Q03** Compare one capability view and the application map against an
architect's expectation: *would you put this on a slide without editing?*
Yes / with edits (list them) / no (why).
